# Frontend

React single-page app with three areas: public pages, the client area and the staff/owner panel.

| Area | Choice |
|---|---|
| Base | React 19, TypeScript (strict), Vite |
| Routing | TanStack Router with file-based routes |
| Server state | TanStack Query (no global store) |
| UI | Tailwind CSS v4 and shadcn/ui |
| Tests | Vitest and Testing Library |
| Code quality | ESLint (with jsx-a11y), Prettier |

## Requirements

- Node 24, the version pinned in [`../.node-version`](../.node-version).
- pnpm: the version is pinned in `package.json` (`packageManager`), and pnpm switches to it by itself.

New to the project? Set up your environment first: [docs/onboarding/windows-wsl.md](../docs/onboarding/windows-wsl.md).

## Commands

Run them in this folder (`frontend/`).

| Command | What it does |
|---|---|
| `pnpm install` | installs the dependencies from `pnpm-lock.yaml` |
| `pnpm dev` | starts the dev server on http://localhost:5173 with hot reload |
| `pnpm typecheck` | type-checks the whole project |
| `pnpm lint` | ESLint and a Prettier check (the same as CI) |
| `pnpm format` | formats all files with Prettier (the Git hook does it for staged files) |
| `pnpm test` | runs the tests once (`pnpm test:watch` keeps them running) |
| `pnpm build` | type-checks and builds the production version into `dist/` |
| `pnpm preview` | serves the built `dist/` locally |

## Working with the backend

Run the backend in another terminal (`cd backend && ./gradlew bootRun`). The dev server forwards these paths to Spring Boot on http://localhost:8080; everything else is the React app:

| Path | Used for |
|---|---|
| `/api` | the REST API |
| `/oauth2`, `/login`, `/logout` | sign-in and sign-out through Keycloak (from M1) |

The browser sees a single origin (`localhost:5173`), so there is no CORS, and the session cookie set by the backend is sent with every API request. The proxy keeps the `Host` header, so Spring builds its redirects for port 5173. The port is fixed: if 5173 is taken, `pnpm dev` stops with an error instead of moving to another port.

## Project structure

```
src/
  app/          router, providers, routeTree.gen.ts (generated)
  routes/       one file per page (TanStack Router file-based routing)
  features/     code of one feature: booking, my-appointments, staff-calendar, admin-…
  shared/
    ui/         shadcn/ui components
    lib/        helpers: dates, price formatting, cn()
  api/          API client generated by orval (later; never edited by hand)
  test/         test setup
```

Code is grouped by feature, not by file type. A route file stays thin and renders a component from `features/`.

### Routes

Every file in `src/routes` is a page: `index.tsx` is `/`, `admin/services.tsx` would be `/admin/services`, `book/$serviceId.tsx` a page with a parameter. `__root.tsx` is the layout around all pages and the "not found" page.

While `pnpm dev` or `pnpm build` runs, the TanStack plugin regenerates [`src/app/routeTree.gen.ts`](src/app/routeTree.gen.ts). Commit it together with the route change (CI type-checks without starting Vite), and never edit it by hand.

### Server data

Everything that comes from the API goes through TanStack Query hooks; later they are generated by orval. No tokens or user data in `localStorage`: the backend holds the session.

### UI components

Components from [shadcn/ui](https://ui.shadcn.com) are copied into `src/shared/ui`, so they are our code and can be changed. Add one with:

```bash
pnpm dlx shadcn@latest add dialog
```

Style with Tailwind classes and the theme colors (`bg-background`, `text-muted-foreground`, …) instead of fixed colors, so the whole app follows one theme.

## Code quality

- **Formatting:** [Prettier](https://prettier.io), including the order of Tailwind classes. Install the Prettier extension and turn on "format on save", or let the Git hook do it.
- **Linting:** [ESLint](https://eslint.org) in [`eslint.config.js`](eslint.config.js): TypeScript rules that know the types (e.g. a forgotten `await`), React hooks rules, TanStack Query and Router rules, and accessibility rules from [jsx-a11y](https://github.com/jsx-eslint/eslint-plugin-jsx-a11y) (strict). An `<img>` without `alt` or a clickable `<div>` fails `pnpm lint` and blocks the commit.
- Generated files are skipped by both: `src/app/routeTree.gen.ts` and later `src/api`.

## Tests

Test files sit next to the code they test (`*.test.tsx`). [`src/app/App.test.tsx`](src/app/App.test.tsx) shows how to render the whole app at a given address.

## pnpm and supply-chain safety

- pnpm does not run install scripts of dependencies and checks new versions against its supply-chain rules. Exceptions are listed in [`pnpm-workspace.yaml`](pnpm-workspace.yaml): for example, lefthook's install script stays off, and the hooks are installed by our own `prepare` script instead.
- ESLint 10 is used with jsx-a11y 6.10.2, whose package still declares ESLint 9 at most. It works with 10 (it uses no removed APIs), so `pnpm-workspace.yaml` allows it explicitly.
- Some packages ship "agent skills" for AI coding agents. [`pnpm-workspace.yaml`](pnpm-workspace.yaml) declines them; the project's own skills live in `.claude/skills`. If pnpm reports "Agent skills awaiting approval" for a new package, decline it the same way (`pnpm approve '!<package>'`) unless the team decided otherwise.

## Troubleshooting

| Symptom | Fix |
|---|---|
| The Windows browser cannot open http://localhost:5173 | start with `pnpm dev --host` (WSL then listens on all its interfaces) |
| `Port 5173 is already in use` | another `pnpm dev` is still running: close it, or find it with `ss -ltnp \| grep 5173` |
| Requests to `/api` fail with `ECONNREFUSED` in the terminal | the backend is not running: `cd backend && ./gradlew bootRun` |
| `Argument of type '"/about"' is not assignable to parameter of type '"/"'` (or a new route missing in `<Link to>`) | `routeTree.gen.ts` is out of date: run `pnpm dev` once, then commit the regenerated file |
