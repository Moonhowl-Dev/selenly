# Selenly

[![CI](https://github.com/Moonhowl-Dev/selenly/actions/workflows/ci.yml/badge.svg)](https://github.com/Moonhowl-Dev/selenly/actions/workflows/ci.yml)

Appointment booking for service businesses, starting with a single hair salon. Clients book in three steps, staff manage their calendars, and the owner configures services, prices and schedules.

The first version serves one salon, but the data model is multi-tenant from day one (`business_id` in every business table), so a later stage can host many businesses without rewriting the database.

> **Work in progress.** Progress is tracked in the [milestones](https://github.com/Moonhowl-Dev/selenly/milestones).

## Features (stage 1)

- **Clients:** sign up with email and password or a passkey, browse services and free slots, book an appointment, cancel it within the salon's cancellation window, see upcoming and past visits.
- **Staff:** day and week calendar, blocking time, marking visits as completed or no-show, adding a visit for a client who called.
- **Owner:** services and prices, staff and their weekly schedules with exceptions, all calendars side by side, client records, a dashboard.
- **System:** confirmation, cancellation and 24-hour reminder emails; an audit of who created or cancelled each visit.

Out of scope for stage 1: online payments, reviews, salon search, SMS and a native mobile app (the web app is responsive).

## Tech stack

| Area | Choice |
|---|---|
| Backend | Java 25, Spring Boot 4.1, Spring Modulith, Spring Data JPA, Flyway |
| Database | PostgreSQL 18; an exclusion constraint makes double bookings impossible |
| Authentication | Keycloak (OIDC, passkeys) behind a backend-for-frontend: the browser only gets a session cookie, never tokens |
| Frontend | React 19, TypeScript, Vite, TanStack Router and Query, Tailwind CSS v4, shadcn/ui |
| API contract | OpenAPI, with the frontend client generated by orval |
| Tests | JUnit, Testcontainers, Vitest, Testing Library, Playwright |
| Infrastructure | Docker Compose, GitHub Actions, Caddy on a single VPS |

## Getting started

First set up your development environment:

| What | Where |
|---|---|
| First-time setup on Windows (WSL 2) | [docs/onboarding/windows-wsl.md](docs/onboarding/windows-wsl.md) |
| Install the tools in Ubuntu | `./scripts/setup-wsl.sh` |
| Check your environment | `./scripts/doctor.sh` |

Tool versions are pinned in the repository: Java in [`.sdkmanrc`](.sdkmanrc), Node in [`.node-version`](.node-version).

Then start the application in two terminals (Docker must be running):

```bash
cd backend && ./gradlew bootRun                # PostgreSQL, Keycloak, Mailpit and the API on :8080
cd frontend && pnpm install && pnpm dev        # the web app on http://localhost:5173
```

Open <http://localhost:5173>. Details: [backend/README.md](backend/README.md), [frontend/README.md](frontend/README.md), [infra/README.md](infra/README.md).

## Contributing

- Every change goes through a pull request linked to an issue (`Closes #12` in the description; the [template](.github/pull_request_template.md) has a place for it).
- The pull request title follows [Conventional Commits](https://www.conventionalcommits.org/) (`feat:`, `fix:`, `docs:`, `build:` and so on). Pull requests are squash-merged, so the title becomes the commit message on `main`.
- Formatting and linting are automatic: a Git hook ([`lefthook.yml`](lefthook.yml)) formats the staged files before every commit.
- [CI](.github/workflows/ci.yml) runs on every pull request: `./gradlew check` in `backend/` (job **Backend**) and lint, typecheck, tests and build in `frontend/` (job **Frontend**).
- [CodeRabbit](https://coderabbit.ai) reviews every pull request ([`.coderabbit.yaml`](.coderabbit.yaml)). Answer each comment with a fix or a reason, then resolve the thread.
- `main` is protected by the ruleset in [`.github/rulesets/main.json`](.github/rulesets/main.json): no direct pushes or force pushes, and a pull request can be merged only when both CI jobs pass and all review conversations are resolved.
- Architecture decisions are recorded in [docs/adr](docs/adr).
- AI tools (Claude Code, CodeRabbit, MCP servers) share the rules in [`CLAUDE.md`](CLAUDE.md). Setup and working agreements: [docs/ai-tools.md](docs/ai-tools.md).

To change the protection, edit the JSON and apply it (repository admins only):

```bash
id=$(gh api repos/Moonhowl-Dev/selenly/rulesets --jq '.[] | select(.name == "Protect main") | .id')
gh api --method PUT "repos/Moonhowl-Dev/selenly/rulesets/$id" --input .github/rulesets/main.json
```
